### 1. BGM 광고 연동 아키텍처 (Audio Ad-Tech)

사용자의 시각적 피로도를 낮추고 수익을 창출하기 위해 '선택형 오디오 광고'를 도입한다.

- **창작자 UI (생산):** 쇼츠 작성(UC04) 시, 외부 API를 호출하여 '무드별 BGM 리스트'를 제공한다. 창작자가 BGM을 선택하면, 쇼츠 데이터 INSERT 시 해당 `bgm_id`를 함께 저장한다.
- **소비자 UI (소비):** 피드 스와이프(UC01) 시, 서버로부터 전달받은 `bgm_id`를 바탕으로 BGM을 스트리밍한다.
- **UX 제약 사항:** 스토어 심사 통과 및 유저 이탈 방지를 위해 앱 최상단에 [글로벌 음소거(Mute) 토글 버튼]을 배치하며, 기본값(Default) 설정은 유저가 결정할 수 있도록 지원한다.

### 2. 데이터베이스 아키텍처 (No-Local 원칙)

개발 복잡도 감소와 유지보수성 향상을 위해 클라이언트(기기) 내부에 SQLite 등의 임베디드 DB를 사용하지 않는다.

- **마이페이지 동기화:** 로컬 저장소 대신, 클라이언트는 API(`GET /my-shorts?uuid={UUID}`)를 호출하여 메인 DB에서 자신의 작성 히스토리와 실시간 투표율을 한 번에 JOIN하여 가져온다.
- **상태 관리:** 클라이언트는 JWT 토큰 또는 기기 UUID만을 메모리(SharedPreferences / Secure Storage)에 캐싱하여 세션을 유지한다.

### 3. [SAD 및 유지보수 계획] 인프라 마이그레이션 전략

**[인프라 스케일업 및 마이그레이션 계획 (Migration Plan)]**

- **Phase 1 (개발 및 MVP 테스트):**
    - 환경: 로컬 머신 (LG Gram + Ubuntu 22.04 LTS)
    - 네트워크: Cloudflare Tunnel을 통한 무과금 터널링.
    - 목적: 개발 비용 0원 유지 및 실시간 디버깅.
- **Phase 2 (상용 서비스 오픈 및 트래픽 유입 시):**
    - 환경: 클라우드 리눅스 VPS (가상 개인 서버)
    - 추천 타겟: Oracle Cloud (무료 티어), Vultr 또는 AWS Lightsail (월 $5 수준).
    - 전환 소요 시간: 10분 이내 (Zero Downtime 목표).

**[이전 프로세스 (Zero-Code Modification)]**
아키텍처가 철저하게 분리되어 있으므로 소스 코드를 다시 컴파일하거나 수정할 필요가 없습니다.

1. 클라우드 VPS를 대여하여 MySQL 8.4 및 서버 런타임을 설치한다.
2. 로컬 DB 데이터를 덤프(`mysqldump`)하여 클라우드 DB로 밀어 넣는다.
3. 앱 서버 설정 파일인 `.env`를 열어 아래와 같이 단 한 줄만 수정한다.
    - `(기존)` `DB_HOST=127.0.0.1`
    - `(변경)` `DB_HOST=123.456.78.90` (새로 대여한 VPS의 IP 주소)
4. 앱 서버를 재시작하면 전체 시스템이 즉시 클라우드 인프라로 전환되어 24시간 무중단 서비스 체계가 완성된다.
