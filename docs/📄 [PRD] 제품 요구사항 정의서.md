# 📄 [PRD] 제품 요구사항 정의서

## 1. 문서 개요

### 1.1 문서 목적

본 문서는 '익명 텍스트 쇼츠 플랫폼 MVP'의 기능 흐름 및 요구사항을 정의하고, 향후 개발, 운영, 법적 대응, 그리고 인수합병(M&A) 실사 시 시스템 아키텍처의 기준 정보를 제공하는 데 목적이 있다.

### 1.2 개발 배경 및 필요성

기존의 익명 커뮤니티(에브리타임, 블라인드 등)는 게시판 형태의 낡은 UI를 고수하고 있으며, 지속적인 악성 트롤링과 모더레이션(운영) 인건비 증가로 인해 수익성이 악화되는 한계(Death Spiral)를 가지고 있다.
본 시스템은 현대 유저들에게 익숙한 '숏폼(세로 스와이프)' UX를 텍스트에 결합하여 즉각적인 도파민을 제공하고, 시스템 자동화를 통해 인건비와 법적 리스크를 0원으로 수렴시키는 차세대 익명 플랫폼을 제안한다.

### 1.3 용어 정의

- **크레딧 (Token):** 유저가 타인의 쇼츠에 투표를 완료했을 때 획득하는 '글쓰기 권한(재화)'.
- **섀도우 밴 (Shadow Ban):** 악성 유저가 제재당한 사실을 모르게 하여 생태계와 격리시키는 은밀한 차단 기술.
- **고스트 인터랙션 (Ghost Interaction):** 섀도우 밴 당한 유저의 게시물에 시스템이 무작위 시간 간격으로 부여하는 가짜 반응.
- **콜드 스토리지 (Cold Storage):** 경찰 영장 집행 시 제출할 90일 치 과거 데이터를 저비용으로 보관하는 별도의 로그 저장소.

## 2. 시스템 개요

### 2.1 시스템 소개

본 시스템은 시각적 피로도 없이 즉각적인 재미를 유발하는 텍스트 전용 스와이프 앱이다. 글을 쓰기 위해서는 타인의 글을 강제로 읽고 평가해야 하는 '자정 작용의 게임화'를 도입하였으며, 메인 데이터는 24시간 뒤 자동 삭제되어 트래픽 회전율을 극대화한다.

### 2.2 기존 시스템 분석

- **기존 익명 앱 (Yik Yak 등):** 필터링 부재와 극단적 독성으로 인해 일반 유저가 이탈하고 스토어에서 퇴출당함.
- **숏폼 비디오 (TikTok 등):** 영상 제작의 허들이 높아 일반인의 콘텐츠 생산 참여율이 저조함.
- **본 시스템의 포지셔닝:** 영상 제작의 부담을 없애고(텍스트), 자동 블라인드 처리와 섀도우 밴을 통해 앱스토어 심사 기준을 우회 및 충족함.

### 2.3 주요 기능 흐름

1. **소비:** 앱 실행 → 세로 스와이프로 24시간 내 작성된 최신 쇼츠 조회.
2. **반응 (크레딧 장전):** 하단 4개 감정 버튼 중 하나 터치 → 크레딧 1스택 획득.
3. **생산:** 크레딧 10스택 달성 → 텍스트 쇼츠 작성 및 업로드.
4. **자정 작용:** 불쾌한 게시물에 '신고하기' 누적 → 시스템이 게시물을 즉시 은폐하고 작성자를 섀도우 밴 처리.

## 3. 기능 요구사항

### 3.1 사용자 기능 (User Functions)

- **REQ-01 (피드 조회 및 탐색):** 사용자는 앱 실행 시 세로 스와이프 인터페이스를 통해 텍스트 쇼츠 콘텐츠를 1개씩 순차적으로 탐색할 수 있어야 한다.
- **REQ-02 (감정 투표 및 크레딧 획득):** 사용자는 쇼츠 하단에 배치된 4가지 감정 버튼(공감, 경멸, 기괴, 통쾌) 중 하나를 선택하여 투표할 수 있어야 하며, 투표 완료 시 글쓰기 크레딧을 1스택 획득할 수 있어야 한다.
- **REQ-03 (어뮤징 콘텐츠 신고):** 사용자는 불쾌하거나 규정을 위반한 쇼츠를 피드에서 즉시 숨기기 위해 '신고하기' 기능을 실행할 수 있어야 한다.
- **REQ-04 (텍스트 쇼츠 생산):** 일정 자격(10 크레딧 소모)을 갖춘 사용자는 최소 20자에서 최대 100자 이내의 순수 텍스트 쇼츠를 작성하고 서버에 등록할 수 있어야 한다.
- **REQ-05 (작성 히스토리 조회):** 사용자는 마이페이지를 통해 본인이 최근 24시간 이내에 작성한 쇼츠의 실시간 생존 여부와 누적 투표 통계를 확인할 수 있어야 한다.
- **REQ-11 (BGM 설정):** 유저는 쇼츠 작성 시 제공되는 리스트에서 상황에 맞는 배경음악(BGM)을 선택할 수 있어야 하며, 피드 조회 시 해당 BGM을 청취하거나 음소거할 수 있어야 한다.
- **REQ-12 (다국어 피드 격리):** 앱은 최초 실행 시 기기의 OS 언어(Locale)를 자동 감지하여 동일한 언어권의 쇼츠만 피드에 노출해야 하며, 유저가 설정 화면에서 선호 언어를 수동으로 변경할 수 있도록 지원해야 한다.
- **REQ-13 (동적 랭킹 알고리즘):** 피드 정렬 시 단순 누적 추천수가 아닌 '시간 감가상각(Time Decay)' 알고리즘을 적용하여, 신규 작성된 쇼츠가 우선적으로 노출될 수 있는 기회를 보장하고 특정 고인물 콘텐츠의 피드 상단 독점을 방지해야 한다.
- **REQ-14 설정(Settings) 기능:** 유저는 앱 내 설정에서 시스템 언어(다국어 UI)를 수동으로 변경할 수 있으며, 앱 내 효과음 및 BGM 자동 재생 여부(사운드 토글)를 제어할 수 있다.

### 3.2 관리자 및 시스템 기능 (Admin & System Functions)

- **REQ-06 (데이터 라이프사이클 관리):** 시스템은 메인 DB에 등록된 쇼츠 데이터를 업로드 시점 기준 24시간 후에 피드에서 자동 파기해야 한다.
- **REQ-07 (법적 대응 로그 보관):** 시스템은 모든 쇼츠 업로드 즉시 [Timestamp, UUID, 원본 IP, 텍스트 원본]을 콜드 스토리지에 아카이브해야 하며, 90일 경과 시 이를 영구 삭제해야 한다.
- **REQ-08 (악성 어뷰저 섀도우 밴):** 시스템은 누적 신고 임계치를 돌파한 유저 또는 허니팟을 타격한 유저를 블랙리스트에 등록하고, 해당 기기의 업로드 데이터를 피드에서 즉시 격리(덤프)해야 한다.
- **REQ-09 (모더레이션 검증 샌드박스):** 시스템은 스토어 심사관 계정 진입 시 글쓰기 제한을 해제하고, 1회 클릭만으로 즉시 블라인드가 작동하는 별도의 테스트 피드 환경을 제공해야 한다.
- **REQ-10 (데이터 강제 제어):** 관리자는 수사기관의 적법한 영장 집행 또는 시스템 크리티컬 이슈 발생 시, 운영 서버 DB에 직접 접속하여 데이터 행(Row)을 강제 삭제하거나 상태 값을 변경할 수 있어야 한다.

## 4. 비기능 요구사항

- **보안 (API 위조 방어):** 모든 API 요청은 클라이언트에서 발급한 HMAC-SHA256 및 Timestamp 서명이 포함되어야 하며, 서명 불일치 시 서버에서 401 Unauthorized를 반환한다.
- **인프라 및 확장성:** 초기 비용 0원을 위해 로컬 서버(Ubuntu) + Cloudflare Tunnel 환경을 구축하되, 트래픽 폭발에 대비하여 소스 코드 내 DB Connection String은 환경 변수(.env)로 완전 분리한다.
- **데이터베이스 성능:** 메인 피드 조회의 지연을 막기 위해, 삭제 로직(TTL)은 주기적인 Batch 프로세스가 아닌 DB 자체의 특성(예: Redis Cache)이나 쿼리 단에서의 시간 필터링을 활용한다.
- `NFR-01 (로컬 데이터 최소화):` 데이터 파편화 방지 및 유지보수성을 위해 기기 내부의 로컬 DB(SQLite 등) 사용을 금지하고 중앙 서버 DB 동기화를 원칙으로 한다.

## 5. 기대 효과 및 차별성

### 5.1 기존 시스템 대비 개선점 (운영자 관점)

- **유지보수 비용 제로화:** CS(고객 응대)와 게시물 삭제를 시스템(신고하기 룰셋)에 100% 위임하여 모더레이터 인건비가 발생하지 않는다.
- **법적 방어력 확보:** 1시간 후 데이터 파기 및 90일 치 콜드 스토리지 로깅을 통해 방조죄 면책 특권을 기계적으로 확보한다.

### 5.2 사용자 입장 주요 가치 (유저 관점)

- **도파민의 즉각성:** 복잡한 가입 절차나 시각적 자극의 피로도 없이, 직관적인 텍스트만으로 즉각적인 재미를 느낄 수 있다.
- **안전한 배설 창구:** 완전한 익명성이 보장되며, 섀도우 밴에 걸리더라도 본인은 알 수 없어 스트레스 없는 감정 표출이 가능하다.
