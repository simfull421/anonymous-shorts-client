6. 메모리 및 런타임 최적화 (Memory & Runtime Optimization)

- **6.1 제네릭(Generics) 활용을 통한 오브젝트 박싱/언박싱(Boxing/Unboxing) 방지**
    - **배경:** C#(.NET) 백엔드 런타임 환경에서 값 형식(Value Type) 데이터를 `object`나 인터페이스 아키텍처로 다룰 경우, 힙(Heap) 메모리 할당과 GC(가비지 컬렉션) 오버헤드가 발생한다.
    - **규격:** 모든 컬렉션과 데이터 전송 객체(DTO), 엔티티 맵핑 데이터는 묵시적 캐스팅을 원천 차단하는 강력한 형식의 제네릭(`List<T>`, `Dictionary<TKey, TValue>`)만을 사용한다. 런타임 성능 저하(GC Spike)를 방지하기 위해 `ArrayList` 등 비제네릭 레거시 클래스 사용을 금지한다.
- **6.2 슬라이딩 윈도우(Sliding Window) 방식 기반 신고 카운트 연산 최적화**
    - **배경:** 백그라운드 배치 스케줄러가 매시간 전역적으로 유저 카운트를 초기화(Reset)하는 구조는 대규모 테이블 락(Table Lock)과 가비지 메모리를 생성한다.
    - **규격:** 클라이언트 요청 시점 기준 가동되는 슬라이딩 윈도우 구조를 채택한다. 신고하기가 인입될 때마다 단순 로그(`INSERT`)만 누적하고, 검증은 `(uuid, created_at)` 복합 인덱스(Composite Index)를 활용하여 최근 1시간의 로우 건수만 계산(`COUNT`)하는 인덱스 스캔 방식으로 메모리 파편화를 예방한다.

### 7. 대규모 데이터 파기 및 인프라 보호 전략

- 트래픽이 가장 적은 새벽 시간대(예: 04:00 ~ 04:10)에 **'10분간의 정기 최적화 점검(Maintenance Window)'**을 도입한다.

이 시간 동안 클라이언트의 DB 접근을 차단하여 테이블 락(Lock)을 방지하고, 24시간이 경과한 초고휘발성 데이터를 한 번의 쿼리로 안전하고 완벽하게 소각(DELETE)한다.

점검 화면에는 "활발한 트래픽 정리 중"이라는 문구를 노출하여 유저에게 서비스 활성도에 대한 긍정적인 심리적 효과(Social Proof)를 제공한다.
